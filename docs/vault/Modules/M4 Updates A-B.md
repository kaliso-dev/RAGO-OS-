# M4 Updates A-B

> Phase A. Statut : **EN COURS** — code écrit le 13/11/2026, testé sans matériel seulement (fausses racines, loop devices avec TPM émulé, VM qemu UEFI avec Secure Boot actif et TPM émulé) ; **jamais testé sur vrai matériel**. Fusionné dans `main` (PR #7, 13/11). **En attente de matériel** : vrai firmware et vrai TPM (PCR 0, 7 et 11 mesurés et stables), chaîne shim → systemd-boot (non testée : la VM a la clé MOK dans la db), le noyau Rago dans l'UKI (la VM embarque le noyau Ubuntu), mkinitcpio réel, le temps réel d'une mise à jour. Retour à [[Projet]], carte [[Architecture]], voir [[Sécurité et boot]].

**Objectif.** Système redondant en deux slots A / B : une mise à jour écrit le slot **inactif**, le redémarrage suivant l'essaie une fois, il devient le défaut s'il démarre, sinon retour automatique sur l'ancien. Chaque slot démarre par **son UKI signée** (fin du trou « devant la machine » de [[M3 Chiffrement LUKS]]).

## Ce qu'il fait
- **Deux racines complètes** sur les volumes chiffrés de M3 (`rago-a`, `rago-b`, ouverts sous le nom `rago-root`), le swap d'hibernation partagé. Le slot en marche est celui dont le volume LUKS porte `/`. **Le slot en marche n'est jamais écrit**, ni le dernier bon connu tant que le démarrage en cours n'est pas confirmé.
- **UKI signée par slot** : `EFI/Linux/rago-a.efi` et `rago-b.efi` sur l'ESP = noyau (celui de M0 : `pkgbase` = `linux-rago`, sinon le plus récent) + initramfs **fraîche du slot** (sa crypttab, faite par dracut ou mkinitcpio dans sa racine) + ligne de commande (`kernel.conf` de M0 + `rd.shell=0 rd.emergency=reboot`) + `os-release` + une section `.rago` (slot, noyau, version, date, phases PCR 11 ; non mesurée), construite par `ukify` avec le systemd-stub **du slot**, signée par la **clé MOK de M0** (`sbsign`). Avant de la poser : sections présentes, slot juste, signature vérifiée, et le noyau embarqué **ne doit pas** être signé par la clé MOK (sorti de l'UKI, il démarrerait seul avec n'importe quelle initramfs) : un noyau déjà signé MOK (celui de M0 d'avant M4) perd cette signature (`sbattach --remove`) avant d'être embarqué. Secure Boot refuse une UKI modifiée (prouvé en VM).
- **systemd-boot** : entrées de type 2 (UKI), `editor no` dans `loader.conf` ; le défaut (dernier slot bon connu) est écrit dans la variable EFI (`bootctl set-default`) **et** dans `loader.conf` (si la NVRAM est effacée) ; l'essai passe par l'entrée à usage unique (`bootctl set-oneshot`).
- **`setup`** (sur le système installé par M0 + M3) : réglages, outils, services, module dracut `systemd-pcrextend` (barrière PCR 11 dans l'initramfs), UKI du slot en marche, jetons TPM (passphrase), puis essai de l'UKI au redémarrage ; l'entrée de M0 (`rago.conf`) reste le repli jusqu'à la confirmation, puis elle est retirée **avec son noyau nu signé** (il démarrerait avec n'importe quelle initramfs).
- **`apply --clone`** : copie du slot en marche (rsync, sans `/home` s'il est à part, sans l'état de M4), `--run` lancé dans la copie en chroot (`RAGO_UPDATE_TARGET_SLOT` posé, `--bind` pour monter un dossier, ex. le dépôt), réglages du slot (M3 : sa crypttab ; M4), UKI construite **depuis la racine du slot**, jetons TPM, essai armé. **`apply --image`** : archive tar signée d'une racine (pour [[M13 Build ISO]]), vérifiée avec les clés publiques de `/etc/rago/update-keys/` (aucune clé = refusé), fichiers propres à la machine gardés (`RAGO_AB_KEEP` : `/etc/rago`, comptes, réseau, ssh, bluetooth…) ; refusé si `/home` est dans la racine (la nouvelle image ne l'aurait pas). Tout se fait dans un espace de montage privé ; le slot cible perd son entrée de démarrage pendant l'écriture (jamais un slot à moitié écrit au menu).
- **Essai et retour arrière** : au redémarrage, systemd-boot démarre l'entrée d'essai une seule fois. Le générateur arme le chien de garde : `multi-user.target` en `RAGO_AB_TRIAL_TIMEOUT` s (900 par défaut), sinon redémarrage forcé ; mode de secours = redémarrage immédiat ; dans l'initramfs, `rd.emergency=reboot`. Au redémarrage, l'entrée à usage unique est consommée : systemd-boot reprend le défaut, l'ancien slot, qui note « ÉCHEC de l'essai de … ». Réussi : `rago-update-confirm` en fait le défaut (une UKI `.next` est renommée), vérifie que **PCR 11 mesuré = prédit** (sinon : `RAGO_AB_PCR11=0`, dégradation), retire les jetons TPM devenus inutiles.
- **`uki`** : nouvelle UKI du slot en marche (ligne de commande ou initramfs changées) en `rago-<slot>.next.efi`, essayée au redémarrage, l'ancienne reste le repli. **`switch`** : démarrer l'autre slot une fois ; **`rollback`** : l'autre slot redevient le défaut. **`status`**, **`check`** (prérequis), **`verify`** (fichiers, services, signatures, slot des UKI, `rd.shell=0`, entrées étrangères, noyau nu signé sur l'ESP, défaut, Secure Boot, PCR 11 mesuré = prédit, jetons TPM ; code 0 / 1 / 3 = redémarrage attendu).

## TPM : PCR 11 et re-scellement
- **Un jeton TPM par entrée de démarrage** (dans [[M3 Chiffrement LUKS]]) : racine A ← entrées du slot A, racine B ← entrées du slot B, swap ← toutes. Jeton d'une UKI : **PCR 0 + 7 + 11**, PCR 11 étant la valeur que systemd-stub y mesurera, **prédite depuis le fichier** avant le redémarrage (sections `.linux .osrel .cmdline .initrd .ucode .splash .dtb .uname .sbat .pcrpkey` dans cet ordre, nom puis contenu, puis la phase `enter-initrd` de systemd-pcrphase) ; `systemd-cryptenroll --tpm2-pcrs=0+7+11:sha256=<valeur prédite>` (systemd ≥ 254). Après l'initramfs, `leave-initrd` change PCR 11 : le système démarré ne peut plus redemander la clé au TPM.
- **Changement de slot ou d'UKI = `reseal`** : `setup`, `apply`, `uki`, `switch`, `rollback` lancent `rago-encryption reseal` (avec la passphrase de secours : `--passphrase-file` ou terminal) ; il ajoute les jetons qui manquent puis retire ceux qui ne servent plus. **La passphrase de secours n'est jamais retirée** (vérifié après chaque retrait).
- **Si le re-scellement échoue** (pas de passphrase sous la main, TPM en panne…) : rien n'est bloqué, c'est dit et journalisé ; au démarrage par la nouvelle entrée, la passphrase de secours est demandée, puis `sudo rago-encryption reseal` (prouvé en VM).
- Seules les UKI **signées par la clé MOK** reçoivent un jeton (une UKI déposée par quelqu'un d'autre sur l'ESP n'est jamais enrôlée), et pas une UKI d'un slot posée sous le nom de l'autre (section `.rago`). Si l'ESP ne montre aucune entrée du slot en marche (ESP pas montée), rien n'est changé.

## Dégradation, jamais de brique
- **Pas d'UKI possible** (ukify, systemd-stub, clé MOK ou sbsigntools absents) : entrée de repli `rago-a.conf` (noyau signé + initramfs du slot dans `rago/a/` sur l'ESP), TPM en **PCR 0 + 7** comme M3 ; dit et journalisé (le trou « devant la machine » reste ouvert tant qu'une telle entrée existe).
- **PCR 11 pas prédictible** (sections que la prédiction ne connaît pas : `.profile`, `.dtbauto`, `.hwids`, `.efifw` ; UKI sans section `.rago` ; contenu de l'initramfs illisible ; systemd < 254) : jeton PCR 0 + 7 pour cette entrée, signalé. **Mesuré ≠ prédit** à la confirmation : `RAGO_AB_PCR11=0` (tous les jetons en PCR 0 + 7 au prochain `reseal`), signalé et journalisé.
- **Initramfs sans systemd-pcrphase** : prédiction sans la barrière `enter-initrd`, avertie.

## Ce que M4 change dans M0 et M3
- [[M0 Noyau scx_rago]] (mode A/B = `/etc/rago/update.conf` présent) : `install` refusé sur le slot en marche (passer par `rago-update apply --clone --bind <dépôt> --run "<dépôt>/kernel/build_rago_kernel.sh install"`), dans le slot écrit il range le noyau avec ses modules (`/usr/lib/modules/<version>/vmlinuz`, `pkgbase`) sans signer ni toucher l'ESP ; `sign` refusé (un noyau nu signé rejouerait PCR 11) ; `bootloader` : systemd-boot signé, pas de `rago.conf`, puis `rago-update uki`. Sans M4, M0 marche comme avant ; corrigé au passage : systemd-boot signé posé explicitement (`bootctl update` ne remplaçait pas un systemd-boot non signé de même version).
- [[M3 Chiffrement LUKS]] : jetons TPM par entrée (ci-dessus), `prune-tpm` (retire seulement, sans passphrase, et seulement quand chaque entrée a déjà son jeton), `--esp`, `tpm-check` qui compte les jetons manquants (`a=ok|refused|no-entry`).

## Utilisation (sur la machine, après M0 + M3)
1. `sudo host/manage_atomic_updates.sh check` (n'écrit rien).
2. `sudo host/manage_atomic_updates.sh setup` (passphrase de secours demandée ; si le TPM a été enrôlé depuis l'installateur, elle a sans doute déjà été demandée à ce démarrage : normal, voir [[M12 Installateur]]), redémarrer : l'UKI du slot A est essayée, puis confirmée toute seule ; `sudo rago-update verify`.
3. Mise à jour : `sudo rago-update apply --clone --run "…"` (ou `--image` signée, plus tard avec [[M13 Build ISO]]), redémarrer ; si le nouveau slot ne démarre pas, retour automatique ; `rago-update status`.
4. Noyau M0 : `sudo rago-update apply --clone --bind <dépôt> --run "<dépôt>/kernel/build_rago_kernel.sh install"`.

## Exigence pour le micro-Windows (décision du 14/11)
« passer les cumulatifs courants via -UpdatePath à chaque reconstruction de l'image » : le micro-Windows ne se met pas à jour en ligne ([[M5 Micro-Windows]]) ; quand une mise à jour de Rago reconstruit son image, elle doit intégrer les mises à jour cumulatives du moment (`windows/compile_micro_engine.ps1 -UpdatePath`). Rien n'est codé dans M4 pour ça (M4 met à jour la racine Linux) ; à faire quand la reconstruction de Windows sera conçue ([[Questions ouvertes]]).
