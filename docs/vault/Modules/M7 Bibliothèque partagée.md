# M7 Bibliothèque partagée

> Phase B. Statut : **EN COURS** — code écrit le 14/11 sur la branche `claude/m7-bibliotheque-partagee` (une seule PR vers `main`, à relire par Sofiene), puis corrigé après une relecture indépendante (même jour, voir plus bas). Côté Linux testé en conteneur et en VM qemu (vrai pilote ntfs3) ; côté Windows **jamais exécuté (Windows, conteneur Linux)**, validé seulement par lecture ; **jamais testé sur matériel**. **Objectif.** Installer et gérer ses jeux Windows depuis Rago ; le micro-Windows ([[M5 Micro-Windows]]) les lance à vitesse native. ## Comment ça marche
- **RAGO-LIB** : partition NTFS (type GPT « Microsoft basic data », étiquette `RAGO-LIB`) ; jeux dans `Games\Steam`, `Games\Epic`, `Games\Riot` ; `.rago\` : `library.json`, fiches `games\<clé>.json` (écrites par Windows, lues par Linux), `cache\` (métadonnées des clients). Lettre fixe **`L:`** côté Windows (les manifestes des clients gardent le chemin).
- **RAGO-COMM\library\** (FAT32 de M5) : `windows-state.json` (Windows : `running` / `off`, `lib.found`, `lib.offline`), `partition.json` (Linux, à chaque montage et à chaque requête : PARTUUID + numéro de série NTFS de RAGO-LIB ; Windows garde aussi une copie locale du PARTUUID quand il a trouvé RAGO-LIB par son étiquette), `requests\<id>.json` (Linux), `results\<id>.json` (Windows : `waiting_user`, `running`, `done`, `failed`, `cancelled`), `linux-confirm.json` (Linux). Identifiants : `install|launch-steam|epic|riot-<slug>` ; mêmes expressions des deux côtés (testé).
- **Installation toujours dans Windows** : l'agent ouvre le client officiel au bon endroit (`steam://install/<id>`, URI d'Epic, installateur Riot), le joueur choisit le dossier `L:\Games\…` (aucun client ne le permet sans lui de façon documentée), l'agent suit la fin (manifeste Steam, `.item` d'Epic, **tous** les fichiers principaux Riot) et écrit le résultat. Un jeu installé ailleurs que sur RAGO-LIB est signalé en échec, rien n'est déplacé. Une installation commencée lors d'une session précédente rouvre son client une fois par session ; échec après 48 h passées dans Windows (le temps sous Linux ne compte pas) ou trois erreurs de suite ; un client n'est installé qu'une fois par session. Installateurs des clients téléchargés chez l'éditeur, **signature Authenticode vérifiée** : valide, et nom du signataire (CN) égal à celui de l'éditeur (motif ancré, noms exacts à vérifier), https aussi après les redirections ; rien n'est redistribué.
- **Finalisation** (« VC++ / .NET / registre ») : les prérequis de chaque jeu sont posés par le client officiel (Steam rejoue ses scripts d'installation au premier lancement, Epic installe les prérequis). Au démarrage (SYSTEM), l'agent vérifie le runtime VC++ 2015-2022 et installe ceux de `C:\Rago\redist` (fournis par le joueur, `-RedistPath`) ; **dans la session du joueur** (jamais en SYSTEM : RAGO-LIB est modifiable par les Utilisateurs), après une reconstruction de Windows, il remet le `.item` d'Epic et le `product_settings.yaml` de Riot depuis `.rago\cache\` (**méthode non officielle, à vérifier**) ; il note la finalisation par installation de Windows (`MachineGuid`), seulement si le runtime VC++ est là.

## Règle de sûreté : jamais les deux OS sur RAGO-LIB (décision du 14/11)
NTFS n'a aucun verrou entre deux systèmes ; le switch ([[M6 Fast OS Switch]]) garantit un seul OS actif.
1. **Windows** écrit `running` (et vide le cache de RAGO-COMM) **avant** que l'agent mette RAGO-LIB en ligne, sur `L:` seulement (une autre lettre posée d'office par Windows est retirée). Sans RAGO-COMM, l'agent ne la met pas en ligne ; s'il ne s'en sert pas (pas de RAGO-COMM, lettre prise, volume sale) et que Windows l'a montée d'office (premier démarrage, ou `/P` pas gardé : à vérifier), il la remet hors ligne. Un volume marqué « sale » (`FSCTL_IS_VOLUME_DIRTY`) est réparé hors ligne (`Repair-Volume -OfflineScanAndFix`, comme `chkdsk /f`) avant toute écriture ; sinon remis hors ligne. À l'arrêt (script d'arrêt de la stratégie de groupe locale, SYSTEM) : marque « arrêt commencé », attente d'une mise en ligne en cours (verrou commun avec `-Boot`, 240 s au plus ; sans le verrou, `offline` est écrit faux), vidage, `mountvol L:\ /P` (démonte et met hors ligne), **confirmation par Windows** que le volume est hors ligne (`IOCTL_VOLUME_IS_OFFLINE`), puis `off`. `offline` n'est jamais écrit vrai sans cette confirmation ; `found: false` seulement si la recherche a abouti sans erreur et que ce démarrage n'a jamais eu RAGO-LIB en ligne.
2. **Linux** ne monte en écriture que si (a) RAGO-COMM dit `off` avec RAGO-LIB hors ligne (ou pas trouvée, sans erreur ni mise en ligne), ou le joueur a certifié Windows éteint (`confirm-windows-off`, valable seulement pour le fichier d'état qu'il a vu, empreinte sha256), **et** (b) le volume est propre sur le disque : bit « sale » éteint, `$LogFile` vide ou propre (règle de ntfs-3g refaite : page de redémarrage la plus récente en version 2.0 = cache de Windows, hibernation ou démarrage rapide ; clients encore ouverts sans le drapeau « propre » = arrêt brutal ; plus strict que ntfs-3g : une page marquée par chkdsk ou d'une version autre que 1.1 / 2.0, un en-tête incohérent ou un journal dont l'enregistrement de base ne donne pas toutes les plages = doute). Au moindre doute : **lecture seule**, jamais `force`.
3. **Pas d'hibernation de Linux** tant qu'un volume NTFS est monté (unité exigée par `systemd-hibernate`, `systemd-hybrid-sleep`, `systemd-suspend-then-hibernate` ; elle ne touche pas RAGO-COMM). « Monté » se juge aussi au **périphérique** : un volume démonté ici mais encore ouvert ailleurs (autre espace de noms — une mise à jour [[M4 Updates A-B]] en cours tourne dans un espace de noms privé qui copie les montages — ou démontage différé) compte comme monté : `umount` répond code 1 (« NE PAS passer sous Windows »), le garde refuse l'hibernation, `mount` refuse (le noyau réutiliserait l'ancien montage sans relire le disque). Un verrou (`flock`) empêche un montage de croiser le garde ; `mount` refuse aussi pendant qu'une veille démarre. **M6 doit faire `rago-library umount` (code 0) avant de basculer et d'hiberner**, et hiberner par systemd.

## Relecture indépendante (14/11)
Cinq relecteurs séparés (sûreté Linux, lecture du NTFS, agent Windows, contrat entre les deux, contraintes et honnêteté), chaque défaut contre-vérifié par un autre. Corrigés, avec un test chacun :
- **Linux** : un volume démonté ici mais encore ouvert ailleurs (espace de noms privé d'une mise à jour M4, démontage différé) passait pour démonté (garde, `umount`, `mount` regardaient seulement le tableau des montages) → contrôle du périphérique (`open(O_EXCL)`) ; garde et `mount` sans verrou commun ; pages du journal NTFS : CHKD rangée par le mauvais numéro, en-têtes acceptés que ntfs-3g refuse, plages du journal incomplètes, attribut tronqué qui faisait planter le contrôle (même la lecture seule était perdue) ; `found: false` avec une erreur accepté comme « Windows n'avait pas RAGO-LIB » ; `partition.json` écrit seulement au montage.
- **Windows** : le motif du chemin `\\?\Volume{…}\` dans le contrôle « hors ligne » ne reconnaissait jamais un vrai chemin (Windows n'aurait jamais confirmé « hors ligne » : Linux toujours en lecture seule) ; volume « sale » jamais réparé (hors ligne au démarrage, autochk ne le voit pas) ; démarrage et arrêt pouvaient se croiser ; arrêt raté écrit `found: false` ; installations reprises après un redémarrage jamais relancées, délai compté avec les jours passés sous Linux, erreurs répétées sans fin (téléchargements et fenêtres UAC) ; Riot « fini » dès un seul fichier ; sortie d'erreur de `mountvol` / `icacls` qui pouvait devenir une exception (PowerShell 5.1) ; lettre posée d'office par Windows gardée à côté de `L:` ; RAGO-LIB montée d'office par Windows laissée en ligne quand l'agent ne s'en sert pas ; **SYSTEM lisait les fiches de RAGO-LIB (modifiables par les Utilisateurs) et écrivait d'après elles dans `%ProgramData%`** (chemin d'élévation de droits) → finalisation passée dans la session du joueur ; signataire cherché comme un bout de texte dans le DN (« Valvetronic » passait) → nom exact ; textes qui affirmaient des comportements de clients non vérifiés.
- Contre-vérification : 23 signalements, tous traités ; un seul jugé surtout infondé (textes sur VC++ et Riot, pas montrés au joueur comme des faits), formulations rendues prudentes quand même.

## Ce que les autres modules doivent faire
- [[M6 Fast OS Switch]] : `rago-library umount` avant le switch et avant toute hibernation de Linux, et **ne basculer que sur le code 0** (code 1 = RAGO-LIB occupée ou encore ouverte ailleurs, par exemple pendant une mise à jour de [[M4 Updates A-B]]) ; hiberner par systemd (la garde s'y accroche) ; Windows démarre à froid et s'arrête complètement (le script d'arrêt écrit `off`). Les requêtes `launch` serviront au « lancement direct au switch ».
- [[M11 Rago UI]] : appelle `rago-library status --json`, `list --json`, `install`, `launch`, `cancel`, `forget`.
- [[M12 Installateur]] : crée RAGO-LIB (GPT « Microsoft basic data », NTFS, étiquette `RAGO-LIB`, sans le bit « caché ») à côté de RAGO-COMM, puis `rago-library mount` une fois (note le PARTUUID pour Windows) ; installe `host/setup_library.sh`.
