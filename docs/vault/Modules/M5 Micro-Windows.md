# M5 Micro-Windows

> Phase B. Statut : **EN COURS** — code écrit le 14/11/2026. **Jamais testé sur matériel. Jamais exécuté (scripts Windows, conteneur Linux) ; ablation réelle + boot + jeu réel + taille finale en attente de l'ISO et de la machine de Sofiene.** Testés : le côté Linux (hook, RAGO-COMM : conteneur + VM qemu sur deux noyaux) et la lecture statique des fichiers Windows. Branche `claude/project-thread-pq1zgv`, une seule PR vers `main`, à relire par Sofiene avant [[M7 Bibliothèque partagée]]. Retour à [[Projet]], carte [[Architecture]].

**Objectif.** Windows réduit à un moteur de jeu invisible (pas de bureau, pas d'écran de connexion), aligné sur l'anti-triche moderne : la sécurité exigée reste active, son état réel est mesuré et renvoyé à Linux. Aucune dissimulation. BYOL strict : Rago ne distribue jamais Windows, les scripts refusent de tourner sans l'ISO du joueur. Voir [[Micro-Windows]], [[Vanguard On-Demand]].

## Édition de base : Windows 11 Pro 25H2 ou plus (DÉCIDÉ le 14/11)
- Demandé au départ : « Win 11 IoT Enterprise LTSC 25H2 ». **Cette édition n'existe pas** (étude du 14/11, pages Microsoft) : la dernière LTSC est la **LTSC 2024 = 24H2, build 26100** ; IoT Enterprise (non LTSC) existe en 25H2 (build 26200). **Vanguard On-Demand exige Windows 11 25H2 ou plus** (Riot, juin 2026) : une LTSC 2024 n'y a pas droit. Les licences IoT / LTSC sont prévues pour des appareils à usage fixe, et League of Legends refuse les éditions Enterprise.
- **Décision de Sofiene (14/11, carte de décision)** : « Windows 11 Pro 25H2 ou plus » ([[Décisions]]).
- Dans le code : `compile_micro_engine.ps1` prend l'édition **Professional** de l'ISO ; une autre édition seulement sur demande (`-Edition` / `-Index`), signalée dans le rapport (et licence IoT / LTSC avertie). Il refuse tout ce qui n'est pas Windows 11 x64 et **refuse une build sous 26200** (25H2) sauf `-AllowOlderBuild` (essai, sans Vanguard On-Demand). Sur Pro, la télémétrie ne descend pas sous « données requises » (`AllowTelemetry=0` lu comme 1, doc Microsoft) ; le service DiagTrack est coupé quand même.

## Fichiers de code (dans `kaliso-dev/rago-os-`)

Options : `-Edition`, `-Index`, `-AllowOlderBuild`, `-UpdatePath`, `-DriverPath`, `-RedistPath`, `-FinalCompression max|recovery`, `-Hibernation full|off`, `-PageFileMB`, `-PlayerName`, `-ComputerName`, `-UILanguage`, `-InputLocale`, `-TimeZone`, `-InstallToDisk/-InstallToPartition`, `-MakeIso`, `-SkipMeasure`, `-NoNetFx3`, `-AllowUnknownEdition`. Rapports : `m5-plan-report.json` / `m5-build-report.json`.
- `windows/micro_engine_plan.json` — le plan d'ablation (Appx, fonctions à la demande, packs de langue, fonctionnalités, pilotes, services, registre, fichiers), chaque entrée avec sa raison. `keep` l'emporte toujours sur `remove` ; `services.never_touch` = pile de sécurité et anti-triche.
- `windows/autounattend.xml` — installation sans surveillance (modèle réglé par le script : langue, clavier, fuseau, nom du PC, joueur).
- `windows/rago/` — copié dans l'image en `C:\Rago` (SYSTEM et Administrateurs seuls en écriture) :
  - `bin/RagoComm.psm1` — fonctions communes : journaux, JSON sans BOM, partition RAGO-COMM (trouvée par son étiquette, montée dans `C:\Rago\comm` si elle n'a pas de lettre), identifiant de démarrage, test CompactOS.
  - `bin/rago-boot.ps1` — tâche de démarrage (SYSTEM) : garde l'ouverture de session automatique (sans compteur) et le shell Rago, lance la fin d'installation si elle n'a pas tourné, applique le profil de sécurité, puis le rapport de mesure.
  - `bin/rago-security.ps1` — profils `compat_max` / `perf` (ci-dessous), état réel, `-Apply` / `-Set` / `-Status` / `-NoReboot`.
  - `bin/rago-report.ps1` — rapport M5 : RAM au repos, `explorer.exe` / `SearchIndexer`, processus, services, sécurité, taille de `C:` sans pagefile / hiberfil / swapfile, CompactOS, temps noyau → shell.
  - `bin/rago-shell.ps1` — shell provisoire (à la place d'`explorer.exe`) : attend l'état de sécurité de ce démarrage, l'affiche, menu de maintenance (console, console administrateur, navigateur, lancer un programme, rapport, retour à Linux, arrêt). Remplacé par le lanceur de jeu de [[M6 Fast OS Switch]].
  - `setup/firstboot.ps1` — premier démarrage, deux phases (`specialize`, `setupcomplete`), idempotent.
  - `setup/SetupComplete.cmd` — lance la phase `setupcomplete` (copié dans `C:\Windows\Setup\Scripts`).
  - `tasks/rago-boot.xml` — tâche planifiée `\Rago\Boot` (au démarrage, SYSTEM, 15 min max).
- `windows/README.md` — mode d'emploi (construction, clé USB, installation, côté Linux, critère de test).

Côté Linux :
- `host/hooks/windows-security` — le hook attendu par [[M14 Profils par jeu]] : `set` écrit `security/profile.json` dans RAGO-COMM (montée à la demande, écrite par fichier temporaire + fsync, démontée), `status` relit l'état écrit par Windows et les rapports. Python 3, bibliothèque standard.

- `host/setup_windows_security.sh` — `install`, `uninstall`, `check` (hook, unité, partition FAT32 de type GPT « Microsoft basic data »), `status` ; `--root`, `--dry-run`. Ne crée pas la partition (travail de [[M12 Installateur]]).

## Méthode d'ablation (ordre réel du script)
La méthode demandée (1 Appx ; 2 capacités / fonctionnalités / langues ; 3 ResetBase ; 4 pilotes ; 5 services ; 6 shell ; 7 compression ; 8 ménage ; 9 hibernation / pagefile) est suivie, mais **pas dans cet ordre** : le nettoyage du magasin de composants (3) doit venir **après** les retraits (sinon il ne gagne rien) et **avant** l'ajout de .NET 3.5 (activé hors ligne, il reste « en attente » et fait échouer `/StartComponentCleanup` : erreur 0x800F0806, doc Microsoft). Ordre réel :
0. Vérifications : administrateur, Windows PowerShell 5.1, module DISM, source du joueur présente, Windows 11 Pro 25H2+ (ci-dessus), plan sûr (refus si un service protégé est dans `disable`, si la base VBS + HVCI manque, si une entrée touche Defender, `\Services\`, `DeviceGuard\Disable*` ou les KernelShadowStacks), édition et build, DISM assez récent, 40 Go NTFS.
1. Export de l'édition choisie dans une image de travail, montage ; `-UpdatePath` : mises à jour cumulatives du joueur.
2. **Appx** provisionnés : tous retirés sauf Sécurité Windows (`Microsoft.SecHealthUI` + ses bibliothèques), extensions vidéo (AV1, HEVC, VP9, MPEG-2, WebM : cinématiques) et connexion Xbox (`XboxIdentityProvider`, `Xbox.TCUI` : jeux Microsoft vendus sur Steam). Pas de Store, pas d'app Xbox, pas de widgets.
3. **Fonctions à la demande** : retirées seulement Assistance rapide, Hello visage, écriture manuscrite, OCR, reconnaissance vocale, Paint / Outil Capture / Visionneuse XPS (quand l'édition les a en fonctions), et Language.Basic / TextToSpeech des autres langues. **Gardées** : les FOD préinstallées que Microsoft dit de ne pas retirer (« Available Features on Demand », 2026 : IE, MathRecognizer, fonds d'écran, OneSync, OpenSSH client, PowerShell ISE, console d'impression, enregistreur d'actions, fax-scan, WMIC, WordPad, Bloc-notes, base DirectX), le Lecteur Windows Media hérité (vidéos de jeux anciens), les pilotes Ethernet / Wi-Fi, et **toujours les polices** (noms et chat asiatiques). 2 bis : **packs de langue** des autres langues (`Remove-WindowsPackage`). 2 ter : **fonctionnalités** désactivées (SMB1, PowerShell 2, impression, fax, XPS, Work Folders, Recall…) ; MediaPlayback, WindowsMediaPlayer, DirectPlay, .NET 4, Hyper-V gardés.
4. **Pilotes** : seuls les pilotes tiers (oemN.inf) des classes inutiles (imprimante, scanner, modem, fax, lecteur de cartes) sont retirables ; les pilotes inbox ne le sont pas (doc Microsoft). `-DriverPath` ajoute ceux du joueur.
5. **Ruches hors ligne** : services de bruit / d'interface en `Start=4` (indexeur, télémétrie DiagTrack / dmwappush, collecteur de diagnostic, spouleur, fax, SysMain, Windows Update + orchestrateur + réparateur + optimisation de distribution, Insider, cartes, géolocalisation, démo magasin, assistant de compatibilité ; le service des rapports d'erreurs `WerSvc` est gardé, comme le conseille Microsoft, l'envoi étant coupé par stratégie) ; base de sécurité posée puis **relue** (refus de l'image sinon) ; télémétrie au minimum, pas d'apps suggérées, pas d'écran de verrouillage ni d'animation, démarrage rapide coupé, horloge en UTC (comme Linux), petit vidage mémoire, redémarrage sur écran bleu, pas de touches rémanentes, pas de OneDrive au premier démarrage, pas de BitLocker automatique.
6. **Charge utile** `C:\Rago` (verrouillée), `SetupComplete.cmd`, `micro-engine.json` (réglages de la construction). Le shell Winlogon est posé au premier démarrage (pas dans l'image : l'écran d'accueil de Setup ne doit pas être gêné).
7. (= 3 demandé) `dism /Cleanup-Image /StartComponentCleanup /ResetBase`. Puis **.NET 3.5** depuis `sources\sxs` de l'ISO.
8. **Ménage** : `Winre.wim` (environnement de récupération), sauvegardes et caches de WinSxS, journaux, Panther, caches de mise à jour, rapports d'erreurs. **Pas** de purge totale de WinSxS façon « tiny11 core » (casse comctl32 v6, VC++ 2005/2008, .NET).
9. Démontage, **export final** : `max` (LZX, `.wim`, défaut) ou `recovery` (LZMS solide, `.esd`). Note : « LZX solide » n'existe pas dans DISM ; le solide est LZMS (`recovery`). **CompactOS** à l'installation (`Compact` dans autounattend.xml, vérifié et posé au premier démarrage si besoin). Média d'installation (image découpée en `.swm` au-delà de 4 Go pour une clé FAT32), ISO avec `-MakeIso`, puis **mesure**.
10. (= 9 demandé, au premier démarrage) **hibernation gardée** (`powercfg /hibernate on`, type full : demande de Sofiene « le switch M6 s'en sert ») ou coupée (`-Hibernation off`) ; **pagefile fixe minimal** (1024 Mio par défaut).

## Ce qui reste actif (jamais touché)
Secure Boot, TPM 2.0, IOMMU (réglages du firmware), noyau NT, DirectX / WDDM, .NET 4 + 3.5, VC++ (installé depuis `-RedistPath`), pile réseau (Ethernet, Wi-Fi), Defender (`WinDefend`, `WdFilter`, `WdBoot`, `WdNisSvc`, `Sense`), Sécurité Windows, pare-feu (`mpssvc`, `BFE`), liste de blocage des pilotes vulnérables, services des anti-triche (`vgc`, `vgk`, `EasyAntiCheat`, `BEService`, `BEDaisy` : installés avec le jeu, leur démarrage reste celui de leur installateur — la bible disait « forcés en automatique », voir [[Questions ouvertes]]). Base du registre : `DeviceGuard\EnableVirtualizationBasedSecurity=1`, `RequirePlatformSecurityFeatures=1` (Secure Boot), `Locked=0`, HVCI `Enabled=1`, `Locked=0`, `CI\Config\VulnerableDriverBlocklistEnable=1`.

## Profils de sécurité (pilotés par [[M14 Profils par jeu]])
- Linux : `rago-profiled prepare-switch --id <jeu>` → hook `windows-security set` → `security/profile.json` dans RAGO-COMM (sans demande lisible : `compat_max`).
- Windows, à chaque démarrage (`rago-security.ps1 -Apply`, SYSTEM) : `compat_max` = hyperviseur lancé (`hypervisorlaunchtype Auto`) → VBS + HVCI tournent ; `perf` = hyperviseur coupé (`Off`) → VBS / HVCI ne tournent pas (bible : « VBS off → EAC/BattlEye »). La configuration du registre reste celle de `compat_max` dans les deux profils, sans verrou UEFI ; Secure Boot, TPM, IOMMU, Defender, pare-feu, liste de blocage restent dans les deux.
- Un **changement** de profil ne prend effet qu'au démarrage suivant : le script pose le profil, demande au firmware un redémarrage **une seule fois** sur Windows (`bcdedit /set {fwbootmgr} bootsequence {bootmgr}` = BootNext, à usage unique) et redémarre ; garde-fou : jamais deux redémarrages de suite pour le même profil (15 min). Le même profil deux fois de suite ne coûte rien.
- État **réel** mesuré (Win32_DeviceGuard, Secure Boot, TPM, protection DMA, liste de blocage, protection de pile matérielle en mode noyau) → `security/status.json` (lu par Linux : `setup_windows_security.sh status`) et `C:\ProgramData\Rago\security-status.json` (attendu par le shell). Conditions de Vanguard On-Demand **rapportées** (Secure Boot, TPM 2.0, VBS, HVCI, IOMMU, build ≥ 26200) ; le verdict officiel est celui de VGTray (Riot).
- **Protection de pile matérielle en mode noyau** : EAC et BattlEye refusent de charger leur pilote quand elle est active (pages Epic et BattlEye). Rago ne l'active pas et ne la coupe pas ; le shell et `status.json` la montrent.

## Installation et premier démarrage
- `autounattend.xml` : langue / clavier, EULA acceptée, pas de mise à jour dynamique de Setup, image n° 1 en `Compact`, **pas de partitionnement** (Setup demande le disque : rien n'est effacé sans le joueur ; `-InstallToDisk/-InstallToPartition` pour une partition existante), clé de produit demandée seulement si Setup en a besoin (aucune clé dans le dépôt), pas d'écran de compte en ligne / Wi-Fi / confidentialité, compte local `RagoPlayer` (Administrateurs, UAC actif, **mot de passe vide**), ouverture de session automatique. Aucun contournement des exigences matérielles de Windows 11 (TPM, Secure Boot).
- `specialize` (SYSTEM) : `firstboot.ps1 -Phase specialize` — ACL de `C:\Rago` et `C:\ProgramData\Rago`, tâche `\Rago\Boot`, hibernation, pagefile, BCD (pas de réparation automatique en boucle, pas d'attente au menu), profil initial sans redémarrage.
- `SetupComplete.cmd` (ou, si Windows ne le lance pas — clé OEM, doc Microsoft —, `rago-boot.ps1` au premier démarrage) : joueur dans Administrateurs (par SID), ouverture automatique **permanente** (sans `AutoLogonCount`), shell Rago, CompactOS, VC++ / DirectX de `C:\Rago\redist`, ménage. La toute première session peut s'ouvrir une fois avec `explorer.exe`.
- Chaque démarrage : tâche `\Rago\Boot` → `rago-boot.ps1` (ci-dessus) ; le shell attend l'état de sécurité de ce démarrage (120 s max). Après le rapport, **définitions de Defender** prises directement chez Microsoft (`MpCmdRun -SignatureUpdate -MMPC`, 5 min au plus), puisque Windows Update est coupé (À VÉRIFIER : que ce chemin marche sans le service Windows Update).
- Ordre de démarrage UEFI : Windows Setup se met devant Linux → à remettre depuis Linux (`efibootmgr -o`, `windows/README.md`). Le retour à Linux = redémarrage (menu `[L]`, écran bleu, coupure).

## RAGO-COMM (contrat Linux ↔ Windows)
Partition FAT32 de 64 Mio, type GPT « Microsoft basic data », étiquette `RAGO-COMM`, lue **tour à tour** (Linux la monte le temps d'une écriture, `run-rago-comm.mount`). Linux ne monte jamais le NTFS de Windows. Fichiers : `rago-comm.json` (repère), `security/profile.json` (Linux → Windows : `schema 1`, `kind "rago-windows-security"`, `security`, `profile_id`, profil joint, date, source), `security/status.json` (Windows → Linux : profil demandé / en place / effectif, état réel, conditions Vanguard, erreurs), `reports/m5-engine.json` (rapport M5). En M5, Windows démarre à froid et s'éteint complètement (démarrage rapide coupé) : son cache FAT n'est jamais périmé. **Si [[M6 Fast OS Switch]] fait hiberner Windows, il devra démonter RAGO-COMM avant.**

## Taille et RAM
**Rien n'est mesuré** (aucun Windows n'a tourné). Cible de Sofiene : 5-8 Go installés (sans pagefile ni hiberfil). La mesure est prévue à deux endroits : `m5-build-report.json` (image appliquée en CompactOS dans un VHDX, avant le premier démarrage) et `reports/m5-engine.json` (taille réelle de `C:` sans pagefile / hiberfil / swapfile, RAM au repos une minute après l'ouverture du shell). Avec l'hibernation gardée, `hiberfil.sys` ajoute environ 40 % de la RAM (non compté dans la cible).
